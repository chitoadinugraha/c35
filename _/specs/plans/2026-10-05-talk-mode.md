# Talk Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the account-sheet Speak row with a Talk / Chat surface switch. Talk is a one-page voice UI over the same Home thread. Turns are normal prompt messages.

**Architecture:** Talk mode is device-local UI state. It does not create a chat, a topic, or a message role. `PageAiHome` keeps one `ChatStore` thread and one `_composerSend` path. Chat mode renders the thread plus `InComposer`. Talk mode renders `UiTalkStage` for the latest user and assistant rows, and sends through the same `_composerSend`. Shorter replies are an inst row matched only when this turn's `ReqPrompt.talk` is true. That flag is not stored on `ai.chat_msg` and is not shown in the bubble. The speaker icon stays `VoicePrefs.speakEnabled` and only starts the existing read-aloud path. Live Call stays a separate realtime session.

**Tech Stack:** Flutter (`clients/app`), protobuf `ReqPrompt`, `ai.inst` seed, existing `SttService` / `TtsService` / `UiMsgBlocks` / `UiMsgUsage`.

## Global Constraints

- Same `chat_id` and same `ai.chat_msg` rows as Chat mode. Switching surfaces never copies or splits history.
- Do not add a Talk chat kind, topic, or tool.
- Do not route Talk through Live Call (`mod_live`, `ReqLiveStart`).
- Type B steering only: shorter replies come from `inst.talk.brief`, not a hardcoded prompt string in Rust.
- Speak (read aloud) remains `VoicePrefs.speakEnabled`. Talk mode does not replace that pref.
- Usage line uses existing `msgUsageStats` (in, out, duration) and shows only when `PromptUsagePrefs.showUsageStats` is true. There is no separate "read tokens" field.
- Copy: account row title **Talk**, subtitle **Shorter replies, voice input**. Indonesian via existing catalog keys if the sheet is translated; otherwise match the current Speak row, which is hardcoded English.
- Do not commit unless the user asks.
- After Dart edits: `.\_\scripts\dev\verify_flutter_app.ps1`. After `.md` / `.sql` / `.proto`: `.\_\scripts\dev\check_utf8_sources.ps1 -Changed -Fix`. After Rust compose edits: `cd servers; cargo build -p server_ai`.

## Locked behavior

| Piece | Behavior |
|---|---|
| Account sheet | Speak row becomes Talk. On enters Talk mode. Off returns to Chat mode on the same thread. |
| Talk page | Existing home header (wifi, version, avatar). Large latest assistant text. `UiMsgBlocks` under it when the latest assistant row has blocks. Usage line under that when the setting is on. Last user transcript strip. Bottom bar: attach, mic, speaker icon, model icon. |
| Leave Talk | Account toggle off, and a Chat control on the Talk page (top start, chevron). Both call `VoicePrefs.setTalkEnabled(false)`. |
| Send | Mic final transcript, or attach plus transcript, calls existing `_composerSend` with `talk: true` on `ReqPrompt`. |
| Streaming | Live assistant text is the stream already written by `msgStreamContent`. No second typewriter after the turn ends. Entering Talk on an old turn shows the full saved text immediately. |
| Speaker icon | Toggles `speakEnabled`. When on, the existing end-of-turn `_speak` runs. Starting the mic calls `TtsService.stop`. |
| Shorter replies | Every Talk send, whether or not the speaker icon is on. Chat sends stay long. |
| Model | Same `_model` / `_modelPut` as the composer. Icon only. |
| Attach | Same attachment picker as `InComposer`. Staged files send with the next transcript. |
| Mic while busy | Becomes Stop and calls `_abortPrompt`. |

```
header (existing home bar, plus a Chat chevron at the start)
latest assistant text (large; stream while busy)
UiMsgBlocks for that row, when blocks exist
usage: in · out · duration, only if PromptUsagePrefs.showUsageStats
last user transcript (interim STT while listening)
attach          mic          speaker          model
```

### Task 4: Home wiring

**Files:**
- Modify: `clients/app/lib/pages/page_ai_home.dart`
- Modify: `clients/app/lib/c/chat/chat_conn.dart` (`promptSend`)
- Modify: the Dart prompt request builder that sets `ReqPrompt` fields

**Interfaces:**
- Consumes: `VoicePrefs.talkEnabled`, `UiTalkStage`, `ReqPrompt.talk`
- Produces: Talk sends and Chat sends share `_composerSend`

- [ ] **Step 1: Extend `promptSend`**

Add `bool talk = false`. Set `req.talk = talk` on `ReqPrompt`. Default false so every existing caller stays a Chat send.

- [ ] **Step 2: Swap the body in `_chatColumn`**

When `VoicePrefs.instance.talkEnabled`:

- Keep `_chatHeader`.
- Replace `_threadBody` and `InComposer` with `UiTalkStage`.
- `assistant` = last `activeMsgs` row with `role == 'assistant'`.
- `userText` = interim STT text while listening, otherwise the content of the last `role == 'user'` row.
- `blocks` = `ChatBlock.decodeList` of that assistant row.
- `usage` = `msgUsageStats(assistant)` when the row exists.
- `busy` = `_store.promptBusyFor(_store.activeChatId)`.
- `onChat` = `VoicePrefs.instance.setTalkEnabled(false)`.
- `onMic` = busy ? `_abortPrompt` : start `SttService` the same way `InComposer` does (`startRecording`, `onAutoStop` transcribe, then `_composerSend(text, staged, talk: true)`). On mic start, `TtsService.instance.stop()`.
- `onSpeak` = `setSpeakEnabled(!speakEnabled)`.
- `onAttach` = the composer attach path. Keep staged files on the home state until send.
- `onModel` = the same menu `_modelPut` already opens from `InComposer`.

`_composerSend` gains `bool talk = false` and passes it to `promptSend`. The existing `_speak` block stays gated on `speakEnabled` only.

Wrap the stage in `ListenableBuilder` on `VoicePrefs.instance` so the account toggle rebuilds the column.
