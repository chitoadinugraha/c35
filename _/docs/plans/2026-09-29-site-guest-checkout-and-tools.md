**Goal:** Complete the remaining guest e-commerce storefront loop on compiled sites (interactive cart drawer, checkout modal, `/v1/site/guest-order/put`), guest contact lead capture (`/v1/site/guest-contact/put`), and add the missing AI chat tools (`site.domain_put`, `site.domain_verify`, `site.draft_get`, `site.order_status`) with `inst` prompt steering.

---

## Background & Architecture

1. **Guest Storefront Runtime**:
   - Server-compiled HTML generated by `mod_site/src/render.rs` currently renders static `<a href="#p{pid}">` links for products.
   - The backend already has high-performance guest order endpoints: `/v1/site/guest-order/put` and `/v1/site/guest-order/get` in `wire_http` and `c35_mod_tx`.
   - We will inject a zero-build client-side runtime (Alpine.js or lightweight standalone vanilla script) into `render.rs` that renders an "Add to Cart" button on product cards, a floating bottom cart bar, and a checkout modal supporting cash/transfer/QRIS and customer notes.

2. **Guest Contact Submission**:
   - `contact_form` blocks currently render an HTML `<form action='#contact'>`.
   - We will add `/v1/site/guest-contact/put` to `wire_http`, storing submitted visitor leads directly into `site.contact` (with `source = 'guest_form'`).

3. **Expanded Chat Tools (`mod_chat`)**:
   - Users currently cannot configure custom domains or check order fulfillment state via Home chat.
   - Adding `site.domain_put`, `site.domain_verify`, `site.draft_get`, and `site.order_status` empowers natural language assistant workflows for all site management tasks.

## Wave 2 — Site AI Chat Tools Expansion

### Track 2: Custom Domain Tools in `mod_chat`
- [ ] **2.1** In `servers/crates/mod_chat/src/tools/builtin/site.rs`, implement `site.domain_put`:
  - Args: `hostname: String`, optional `site_iid: i64`.
  - Resolves site, validates hostname format (ASCII lowercase, no scheme/path, not platform host).
  - Calls `site_domain_upsert` from `c35_mod_site`.
  - Returns DNS instructions (CNAME target `site.alienai.id`).
- [ ] **2.2** Implement `site.domain_verify`:
  - Args: `hostname: String`, optional `site_iid: i64`.
  - Calls `site_domain_verify` from `c35_mod_site`.
  - Returns verification status (`ready`, `pending`, `failed`) and TLS status.
- [ ] **2.3** Register both tools in `servers/crates/mod_chat/src/tools/builtin/mod.rs` and dispatcher.

### Track 3: Draft Inspect & Order Status Tools in `mod_chat`
- [ ] **3.1** In `site.rs`, implement `site.draft_get`:
  - Args: optional `site_iid: i64`.
  - Returns current SiteDoc JSON structure (pages, block types, active theme) for LLM situational awareness.
- [ ] **3.2** In `servers/crates/mod_chat/src/tools/builtin/site_tx.rs`, implement `site.order_status`:
  - Args: `tx_id: i64`, `state: String` (`draft`, `pending`, `waiting_payment`, `ok`, `cancelled`), optional `note: String`.
  - Updates `site.tx.state` and appends note to `tx_data_json`.
  - Returns updated transaction status summary.

### Track 4: `inst.sql` Steering Seeds
