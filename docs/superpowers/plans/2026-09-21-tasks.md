# Tasks (scoped CRUD + UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship server-orchestrated tasks with `TaskScope` (user / device / bot), shared `UiTaskMasterDetail` widget, device Task tab, Settings → Tasks (personal), and JetStream dispatch to remote agents — ported from `D:\cs_agent` task UX.

**Architecture:** Mirror `mod_skill` + `UiSkillMasterDetail` patterns. `ai.task` gains `scope` + `bot_iid` like `ai.skill`. `owner_iid` is always the signed-in user. Device-scoped tasks bind `device_iid`; bot-scoped bind `bot_iid`; user-scoped tasks pick execution device at run time. Server crate `mod_task` owns CRUD + `task_run` lifecycle + NATS JetStream publish + `TaskRunPush` WS fanout. Agent executes `ActDeviceTaskRun` and reports `EvDeviceTaskProgress` / `EvDeviceTaskDone`.

**Tech Stack:** Flutter (`clients/app`), Rust (`servers/crates/mod_task`, `remotes/c_remote_core`), protobuf (`_/schemas/proto/c35/task.proto`), YugabyteDB, NATS JetStream.

## Design (locked for this plan)

### TaskScope

| Scope | `device_iid` | `bot_iid` | Run target |
|-------|--------------|-----------|------------|
| `user` | `0` | `0` | `ReqTaskRunStart.device_iid` required (picker in UI) |
| `device` | remote iid | `0` | same as `task.device_iid` |
| `bot` | `0` | bot iid | server-side stub v1 (`failed` + "Bot executor not implemented") |
| `team` | — | — | **deferred** (schema slot only) |

**Flow (`remote.md`):**

2. `INSERT ai.task_run` status=`queued`

5. Publish `TaskRunPush` → `c35.user.{owner_iid}.task_run`

**Bot scope v1:** insert run with status=`failed`, error=`Bot executor not implemented`, return run (no NATS publish).
